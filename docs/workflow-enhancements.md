# Developer Workflow Enhancements using Kiro DB State

This document outlines the architectural design and feature definitions for advanced developer workflow enhancements that leverage the SQLite database state and file lock data generated by `kiro-cli` and `kiro-sessionizer`.

## Overview of Kiro CLI DB Context
By querying the `conversations_v2` and legacy `conversations` tables in `data.sqlite3`, we have access to:
- `key`: The absolute path of the working directory for each session.
- `conversation_id`: The unique ID (UUID) of the session.
- `value`: A rich JSON state payload including:
  - `transcript` / `history`: The conversational turns between user and AI, including exact user queries and assistant responses.
  - `latest_summary`: Summarizations of older history.
  - `file_line_tracker`: A map of file paths and specific lines read/written during development.
  - `model_info`: The underlying model used for the session.

---

## Feature Architectures

### 1. Workspace Restore (`kiro-sessionizer restore`)
* **Concept**: Reopen files modified or referenced during a specific session.
* **Mechanism**:
  - Read `file_line_tracker` in `value` JSON to extract file paths.
  - Resolve paths against the session's working directory (`key`).
  - Filter out files that no longer exist on the filesystem.
  - Detect and launch the editor (e.g., VS Code via `code`, Cursor via `cursor`, or terminal editors like `vim`, `nano`) or display an interactive list of target files via a sub-`fzf` menu if multiple editors are available or if requested interactively.
* **Fuzzy Finder Integration**: Keybind `ctrl-o` in the main `fzf` list to trigger background workspace restoration.

### 2. Conventional Commit Drafting (`kiro-sessionizer commit-draft`)
* **Concept**: Automatically craft high-quality Git commit messages based on session achievements.
* **Mechanism**:
  - Parse the `latest_summary` and `transcript` from the most recent session.
  - Identify touched files from `file_line_tracker`.
  - Format the commit message according to Conventional Commits (e.g., `feat(ui): add keybindings for restore...`).
  - Print the drafted message directly to `stdout` for piping or manual integration with git templates.

### 3. Chronological Standup/Journal Generator (`kiro-sessionizer journal` and `kiro-sessionizer report`)
* **Concept**: Aggregate development activity for daily standups or a project log.
* **Mechanism**:
  - `journal [project_path]`: Group sessions chronologically by their updated timestamps for a given project directory, rendering a Markdown history of the first user query and the final session summary.
  - `report [--days DAYS] [--project PATH]`: Scan across multiple projects to summarize what was worked on, listing project name, model, message count, paths from `file_line_tracker`, and `latest_summary`.

### 4. Database Pruning and Session Maintenance (`kiro-sessionizer prune`)
* **Concept**: Clean up old, empty, or forgotten sessions to keep the SQLite database fast and small.
* **Mechanism**:
  - Accept `--days` and `--min-messages` filters.
  - Execute standard/safe deletions from `conversations_v2` and legacy `conversations` databases.
  - Provide a dry-run mode (`--dry-run`/default) to preview deletions, an interactive confirmation prompt (`Are you sure? [y/N]`), and a `--apply` flag with `--force` option to execute automatically in non-interactive CI/CD scripts.
  - Clean up corresponding lock and session metadata files under `~/.kiro/sessions/cli/`.

### 5. Quick-Jump (`kiro-sessionizer jump`)
* **Concept**: Direct navigation of the shell to directories containing valid, historical sessions.
* **Mechanism**:
  - Query database to extract unique project working directories (`key`), sorted by recency (`updated_at` DESC).
  - Filter directories using `os.path.abspath` and verify their existence using `os.path.exists()`.
  - Display them via `fzf`. Upon selection, emit `cd [path]` or a tmux navigation command for the shell wrapper to capture and evaluate.
